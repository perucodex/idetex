Instructivo técnico para implementar una nueva balanza

Windows + Python + Flask + Odoo (Shop Floor) • Guía estándar para programadores de la empresa

Arquitectura multi-balanza Odoo vía Apache HTTPS Proxy interno en Odoo Lectura serial (COM)
Arquitectura usada (recomendada):
El navegador no se conecta directo a la balanza. El flujo es:

Frontend Odoo (HTTPS) → Controller Odoo /idtx_scale/peso → Flask en PC de balanza (HTTP:5001)

Esto evita problemas de mixed content, CORS y certificados en cada PC de balanza.

1) Objetivo

Dejar una nueva balanza operativa para que Odoo lea el peso en tiempo real desde Shop Floor con estabilidad (ST/US), y con opción de ingreso manual autorizado como contingencia.

Resultado esperado: al abrir el diálogo en Odoo, el peso aparece en vivo, muestra “Estable/Inestable” y solo permite confirmar cuando el peso es válido y estable.

2) Requisitos previos

2.1 Información mínima que debes tener

  • PC conectada físicamente a la balanza.
  • Puerto serie asignado (ej. COM1, COM3).
  • IP fija de la PC en red (recomendado) o reserva DHCP.
  • Baudrate de la balanza (normalmente 9600).
  • Confirmar si la balanza transmite en continuo o por demanda (si requiere comando).

2.2 Recomendación de red

Usar IP fija para evitar que el registro en Odoo quede apuntando a una IP que cambie.

Ejemplo:
IP PC balanza: 172.16.66.50
Puerto Flask: 5001
Endpoint local: http://172.16.66.50:5001/peso

3) Preparar PC de balanza (Windows)

3.1 Crear carpeta estándar

Crear la carpeta de trabajo:

C:\ScaleServer

Se recomienda que esta carpeta contenga:

  • scale_server.py
  • run_scale_server.bat
  • scale_server.log (se crea solo)
  • venv\ (opcional, si usan entorno virtual)

4) Instalación de Python y dependencias

4.1 Instalar Python

  1. Instalar Python 3.13 (Windows x64).
  2. Marcar Add Python to PATH durante la instalación.

4.2 Verificar instalación

python --version
pip --version

4.3 Instalar dependencias (simple)

cd C:\ScaleServer
pip install flask pyserial

4.4 Instalar dependencias (opcional con entorno virtual)

cd C:\ScaleServer
python -m venv venv
venv\Scripts\activate
pip install flask pyserial

Si la empresa estandariza el uso de venv, usar siempre la opción 4.4.

5) Configuración del archivo scale_server.py

Copiar el archivo estándar de la empresa en C:\ScaleServer\scale_server.py.

5.1 Variables que se deben revisar siempre

SERIAL_PORT = "COM1"      # Cambiar según puerto real
BAUDRATE = 9600           # Cambiar si la balanza usa otro baudrate
HTTP_HOST = "0.0.0.0"     # Dejar así
HTTP_PORT = 5001          # Dejar estándar
READ_COMMAND = None       # Si la balanza es por demanda, configurar comando

5.2 Significado

  • SERIAL_PORT: puerto COM físico de la balanza.
  • BAUDRATE: velocidad serial.
  • READ_COMMAND: comando serial si la balanza no transmite continuamente.
Importante: si la balanza es “por demanda” y no configuras READ_COMMAND, el endpoint puede responder ok: false aunque el puerto esté correcto.

6) Identificar el puerto COM correcto

  1. Abrir Administrador de dispositivos.
  2. Ir a Puertos (COM y LPT).
  3. Ubicar la balanza (ejemplo: USB Serial Port (COM3)).
  4. Copiar ese COM y colocarlo en SERIAL_PORT.

6.1 Ejemplo

Si Windows muestra: USB Serial Port (COM3)
Entonces en scale_server.py:
SERIAL_PORT = "COM3"

7) Prueba local del servidor Flask (primera vez)

7.1 Ejecutar manualmente

Desde CMD en la PC de balanza:

cd C:\ScaleServer
python scale_server.py

7.2 Validar endpoints localmente

Abrir en navegador de la misma PC:

  • http://127.0.0.1:5001/health
  • http://127.0.0.1:5001/status
  • http://127.0.0.1:5001/peso

7.3 Respuesta esperada en /peso

{
  "ok": true,
  "peso": 22.50,
  "unidad": "kg",
  "stable": true,
  "raw": "ST,GS,   22.50KG",
  "age_s": 0.2,
  "port": "COM1",
  "baudrate": 9600
}

Interpretación:

  • ok: true → la lectura está vigente.
  • stable: true → peso estable (ST).
  • stable: false → peso inestable (US).

8) Configurar Firewall de Windows (obligatorio)

El servidor Odoo debe poder conectarse a la PC de balanza por el puerto 5001.

8.1 Crear regla de entrada (TCP 5001)

  1. Abrir Windows Defender Firewall con seguridad avanzada.
  2. Ir a Reglas de entrada → Nueva regla.
  3. Seleccionar Puerto.
  4. TCP → puerto específico: 5001.
  5. Seleccionar Permitir la conexión.
  6. Aplicar a perfiles necesarios (Dominio/Privado).
  7. Nombre sugerido: ScaleServer 5001.
Recomendación de seguridad: si es posible, restringir la regla para permitir solo la IP del servidor Odoo.

9) Probar conectividad desde el servidor Odoo

Desde el servidor Linux donde corre Odoo (o el host donde se ejecuta Odoo), probar:

curl http://IP_PC_BALANZA:5001/health
curl http://IP_PC_BALANZA:5001/peso

Ejemplo

curl http://172.16.66.50:5001/health
curl http://172.16.66.50:5001/peso
Si esto falla, Odoo no podrá leer la balanza. Revisar: IP, firewall, cableado/red, puerto 5001, ejecución del Flask.

10) Inicio automático al arrancar Windows (Programador de tareas)

10.1 Crear script de arranque .bat

Crear C:\ScaleServer\run_scale_server.bat.

Opción A: sin entorno virtual

@echo off
cd /d C:\ScaleServer
python scale_server.py >> C:\ScaleServer\scale_server.log 2>&1

Opción B: con entorno virtual

@echo off
cd /d C:\ScaleServer
call C:\ScaleServer\venv\Scripts\activate.bat
python scale_server.py >> C:\ScaleServer\scale_server.log 2>&1

10.2 Crear tarea en Programador de tareas

  1. Abrir Programador de tareas.
  2. Seleccionar Crear tarea (no “tarea básica”).
  3. General:
    • Nombre: Scale Server
    • ✅ Ejecutar tanto si el usuario inició sesión como si no
    • ✅ Ejecutar con privilegios más altos
  4. Desencadenadores:
    • Nuevo → Al iniciar el sistema
    • (Opcional) retrasar 30 segundos
  5. Acciones:
    • Programa/script: C:\ScaleServer\run_scale_server.bat
  6. Condiciones: desmarcar restricciones no deseadas (ej. energía AC).
  7. Configuración: permitir ejecución manual y reintentos si falla.

10.3 Probar la tarea

En el Programador de tareas, clic derecho → Ejecutar. Luego validar:

http://IP_PC_BALANZA:5001/health

11) Configuración de la nueva balanza en Odoo

11.1 Requisitos del módulo Odoo

El módulo debe tener cargado:

  • Modelo scale.registry con campo ip
  • Controller /idtx_scale/peso (proxy Odoo → balanza)
  • JS + XML del diálogo con lectura en vivo y estado de estabilidad

11.2 Crear/validar equipo en Mantenimiento

  1. Ir a Mantenimiento → Equipos.
  2. Crear o ubicar el equipo asociado a esa balanza (ej. “Balanza Tinte 02”).

11.3 Registrar la balanza en Scale Registry

Crear un registro con:

  • Equipment: equipo de mantenimiento
  • Scale IP: IP de la PC de balanza (ej. 172.16.66.50)
En Scale IP colocar solo la IP (sin http://, sin puerto).

11.4 Validación del endpoint en Odoo

Con sesión iniciada en Odoo, probar en navegador:

https://odoo.gestionidtx.com/idtx_scale/peso?scale_id=ID_DE_LA_BALANZA

Debe devolver JSON con ok, peso, stable.

12) Pruebas end-to-end (Odoo)

  1. Abrir una orden de trabajo en Shop Floor.
  2. Abrir el diálogo para agregar rollo / leer balanza.
  3. Seleccionar la balanza.
  4. Verificar:
    • El peso se actualiza automáticamente.
    • Se muestra Estable o Inestable.
    • El botón Confirm se habilita solo con peso > 0 y estable.

13) Modo manual (contingencia)

Si la balanza falla o no está disponible:

  1. Seleccionar Manual en el diálogo.
  2. Ingresar credenciales de autorización (usuario con permisos definidos).
  3. Ingresar peso manualmente.
  4. Confirmar.
El modo manual debe usarse solo como contingencia. El flujo normal es lectura en vivo de balanza.

14) Checklist de alta de una nueva balanza

PC de balanza (Windows)

  • Python instalado
  • flask y pyserial instalados
  • scale_server.py copiado en C:\ScaleServer
  • SERIAL_PORT correcto (COMx)
  • BAUDRATE correcto
  • /peso responde localmente
  • Puerto 5001 abierto en firewall
  • Tarea programada creada y funcional

Servidor Odoo / Aplicación

  • curl http://IP_BALANZA:5001/peso responde desde servidor Odoo
  • Registro creado en scale.registry con IP correcta
  • /idtx_scale/peso?scale_id=... responde en Odoo
  • En Shop Floor se visualiza peso en vivo
  • Se muestra estado de estabilidad
  • Confirmación de rollo funciona correctamente

15) Errores comunes y solución

15.1 Error: “No se pudo abrir COMx”

Causa: puerto incorrecto o ocupado por otro programa.

Solución: revisar Administrador de dispositivos, validar COM real y cerrar software que use el puerto.

15.2 /peso responde pero ok: false

Causa: no hay lectura reciente, baudrate incorrecto o balanza por demanda sin comando.

Solución: revisar raw, BAUDRATE y READ_COMMAND.

15.3 Odoo no puede conectarse a la balanza

Causa: problema de red o firewall.

Solución: abrir 5001/TCP, probar curl desde servidor Odoo, verificar IP correcta.

15.4 En Odoo aparece “Error reading scale”

Causa probable: endpoint de balanza caído o controller de Odoo no cargado.

Solución: probar /idtx_scale/peso?scale_id=..., revisar logs de Odoo y controllers/__init__.py.

15.5 El peso aparece pero no deja confirmar

Causa: peso 0, peso inestable (US) o faltan empleado/equipo.

Solución: esperar estabilidad, validar selección de datos y peso > 0.

16) Estandarización recomendada (empresa)

16.1 Convención en PC de balanza

  • Carpeta: C:\ScaleServer
  • Puerto HTTP del servicio: 5001
  • Log: C:\ScaleServer\scale_server.log
  • Tarea de Windows: Scale Server

16.2 Convención en Odoo

  • scale.registry.ip = IP fija de la PC de balanza
  • equipment_id = equipo de mantenimiento asociado

16.3 Nota sobre Apache / HTTPS

No se debe crear una ruta Apache por cada balanza. Apache solo proxya Odoo por HTTPS. El acceso a cada balanza se resuelve dinámicamente desde Odoo mediante scale.registry.ip.

Buenas prácticas:
  • Documentar por cada balanza: IP, COM, baudrate, fecha de instalación, responsable.
  • Probar /health y /peso después de cada reinicio de PC.
  • Revisar periódicamente scale_server.log si hay fallas intermitentes.
